## What I do

- **Single-file HTML reports** that open fully styled anywhere, offline —
  Bootstrap 5 CSS + JS and Chart.js are inlined into the file by default
- **Component-driven pages** — stat cards, striped tables, callouts, badges,
  progress bars, nav-tabs, accordions; dark/light theme via `data-bs-theme`
- **Charts** — Chart.js line/bar/doughnut (interactive) and zero-JS inline
  SVG charts (print/no-JS fallback)
- **Mermaid diagrams with fullscreen zoom always on** — click any diagram
  (or its ⛶ button) for a fullscreen overlay with wheel-zoom, drag-pan,
  double-click reset, Esc to close
- **Light/dark toggle on every page by default** — a 🌓 button (top-right)
  flips the whole page between light and dark mode, remembers the choice,
  and re-themes Chart.js charts and Mermaid diagrams automatically
- **Pinned, tested helpers** — formatting, stats and windowing invariants
  carried over from the proven chat-analyzer report library

## When to use me

**Perfect for:**

- Data/performance/benchmark/comparison reports as shareable HTML files
- Dashboards and status pages rendered from computed data
- Analysis write-ups that need charts, tables, and diagrams
- Any document that must look finished without a build step or server

**Use the `pdf` skill instead when** the deliverable must be a PDF.

## Quick start

Pick ONE of two workflows — never start from a blank file:

1. **Template workflow (hand-edited reports).** Copy the starter and edit it
   in place:

   ```bash
   cp skills/html/template.html my_report.html
   ```

   The template is a complete working report (CDN mode, ~15 KB, easy to
   edit): toggle, charts, mermaid zoom, tables all wired up. When done,
   deliver as-is (needs network) or make the single offline file:

   ```bash
   python3 skills/html/scripts/make_inline.py my_report.html   # -> my_report_inline.html
   ```

2. **Scaffold workflow (computed reports — preferred when numbers come
   from data).** Run:

   ```bash
   python3 skills/html/scripts/new_report.py --title "My Report" -o my_report.html
   ```

   (supports `--theme light`, `--mode cdn`). Then edit the generated
   sections in place, or copy the script and import `html_lib` directly:

   ```python
   import sys; sys.path.insert(0, "<skill-dir>/scripts")
   from html_lib import (build_head, build_foot, stat_cards_row, callout,
                         table_html, section_heading, verdict, fnum, fmt_ms,
                         med, pctile, winner, chartjs_canvas, chartjs_script,
                         chartjs_defaults, chartjs_line, chartjs_bar,
                         chartjs_doughnut, mermaid_block, mermaid_init,
                         svg_line_chart, svg_bar_chart_grouped)
   ```

   `html_lib.py` is **Python stdlib only** — no pip installs.

Either way: **read the references before writing markup by hand** —

- `references/component-cookbook.md` — components, theming, structure
- `references/chart-recipes.md` — Chart.js / Mermaid / SVG recipes
- `references/asset-urls.md` — pinned versions, CDN URLs, re-vendor

## Canonical report structure

Follow the established convention (readers know where to look):

1. `<h1>` + `.subtitle` — what, where, when
2. **Outcomes** — computed headline numbers in stat cards
3. Charts and per-period tables
4. **Findings & Caveats** — always state confounds (different days/builds,
   coverage bias, missing metrics)
5. **Verdict** box
6. Appendix — Methodology & Config (optional)
7. `.footer` — "Generated by `<script>` · data sources"

## Asset modes

- `build_head(mode="inline")` (default) — Bootstrap + Chart.js inlined into
  the single HTML file (~500 KB–1 MB); works offline anywhere
- `build_head(mode="cdn")` — jsDelivr links; smallest file, needs network
- **Mermaid is always CDN-only** (`mermaid_init(cdn=True)`); for offline
  reports, vendor mermaid's dist folder and pass `local_path=` (see
  `references/asset-urls.md`)
- `scripts/make_inline.py` converts a finished CDN-mode report (e.g. one
  started from `template.html`) into the single offline file using the
  vendored assets

## Hard rule: Mermaid diagrams get fullscreen zoom, always

Large diagrams are unreadable at fixed page width. **Every Mermaid diagram
ships with fullscreen zoom support by default so it can be read easily.**

- ALWAYS use `mermaid_block(definition)` (wraps the diagram in the
  `diagram-frame` container with the ⛶ affordance) and emit
  `mermaid_init()` exactly once per page, after all diagrams
- NEVER hand-roll a bare `<pre class="mermaid">` — it loses the zoom viewer
- The viewer: click/⛶ → fullscreen overlay, wheel-to-zoom, drag-to-pan,
  double-click reset, Esc/✕/backdrop-click close

## Hard rule: keep the light/dark toggle

Every report ships with the 🌓 toggle (top-right) that flips
`data-bs-theme`, persists the choice in `localStorage`, and re-themes
Chart.js charts (registered by `chartjs_script()`) and Mermaid diagrams
(via `window.__renderMermaid`). It is emitted by `build_head()` by default.

- Do not remove it without a reason (opt out via
  `build_head(theme_toggle=False)`)
- Diagrams re-render with the mermaid theme matching the current page mode
  — no theme parameter is needed anywhere
- Charts created by hand-written `new Chart(...)` calls (instead of
  `chartjs_script()`) will NOT re-theme on toggle — use the helper

## Engineering rules

- **Compute, don't hardcode** — every number in the HTML comes from data
- **NaN guard** — filter `v != v` before any `max()`/`mean()`; a single NaN
  poisons whole charts (the "NaN trap")
- **"no data", never an exception** — missing data renders a muted note
- Numeric table cells right-aligned with tabular numerals (matches the
  `pdf` skill's tables)
- Do not change `med`/`pctile` to interpolated medians — their index
  arithmetic is pinned by tests and published numbers depend on it

## Verification checklist

Before delivering a report:

1. `grep -c ">nan<" report.html` → `0`
2. Open the file with network OFF — everything except Mermaid diagrams must
   still render (inline mode)
3. Click each Mermaid diagram — fullscreen zoom overlay must open
4. Click the 🌓 toggle — page flips light/dark, charts and mermaid diagrams
   re-theme, reload keeps the chosen mode
5. Check numbers against the source data (spot-check at least three)
6. Verify every section states its data source; caveats present if any
   comparison has confounds

Run the library's tests after any change to `html_lib.py`:

```bash
python3 skills/html/scripts/test_html_lib.py
```
